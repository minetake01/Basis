# Auto Translator

Windows版Basisの周囲の音声を、Grok Voice Transcribe 2.0とOpenAI互換のChat Completions APIで翻訳するローカル字幕機能です。初期状態は無効です。モデルのAPIを呼び出すのは、設定して有効にし、対象プレイヤーが発話したときです。

## 利用方法

1. WindowsのBasisクライアント／Unity Editorで、設定 → **自動翻訳**を開きます。
2. xAI APIキー、翻訳APIのベースURL（`https://example.com/v1`のように指定）、モデル名、翻訳APIキーを入力します。ローカルホストの翻訳サーバーのみHTTPも使用できます。
3. 翻訳先言語（初期値: 日本語）と最大話者数（初期値: 8）を設定します。
4. **有効にする**を選び、**保存して適用 / 再接続**を押します。入力変更はこのボタンでまとめて反映します。
5. 聞こえるプレイヤーが話し始めると接続します。頭上に原文と訳文が表示され、途中の原文には `…` が付きます。確定結果は8秒後に消えます。

APIキー欄は保存後に空欄になります。空欄で適用すると保存済みのキーを使います。**停止して保存済みAPIキーを削除**で削除できます。キーはWindowsの現在のユーザーに紐付くDPAPIで暗号化され、`Application.persistentDataPath/net.minetake.auto-translator/`内に保存されます。別のWindowsユーザーへのファイルコピーでは復号できません。

音声はxAIに、文字起こしは設定した翻訳APIに送信します。利用者自身のキーでAPI料金が発生します。音声・会話履歴はローカルに保存せず、字幕を他プレイヤーに配信しません。共有キーや共有バックエンドは含みません。

字幕はネームプレートの子として描画するため、ネームプレートの表示設定・可視性に従います。通常のチャット表示は変更しません。翻訳対象は通常・ささやき・アナウンスの受信音声で、ミュート・ブロック・個別音量ゼロ・全体音量ゼロは除外します。

## 接続と制限

- Grok STTはPCM16／16 kHz、100 ms単位のマルチチャンネル送信です。初期設定では8チャンネルを1本のWebSocketで送ります。話者のいないチャンネルは無音です。入力言語は指定せず、自動認識させます。
- 最大話者数は1〜64。接続ごとに最大8チャンネルです。Grokのマルチチャンネルは2チャンネル以上のため、最大話者数1でも2チャンネル構成（片方は無音）になります。接続数の集約が料金削減になることは保証しません。
- 一度使用したチャンネルを同じ接続内で別の人に割り当てません。必要な接続だけを作り直し、継続中の話者の未送信音声を引き継ぎます。この境界で文字起こしの発話単位は新しくなります。
- 上限時は既存の対象者を維持し、空き枠には発話中の近い相手を入れます。範囲外への移動・退室・ミュート時は解除し、30秒間発話のない話者も接続枠を解放します。
- 訳文は途中の文字起こしに対して最大1秒に1回、発話確定時にも更新します。話者ごとに実行中1件と最新の待機1件、全体で同時4要求です。APIのストリーミング応答は使わず、要求ごとの完成した訳文を表示します。
- 取得バッファ・送信バッファには上限があります。送信バッファは10秒、接続準備は10秒、翻訳要求は20秒を上限とします。認証・通信・形式・バッファのエラーは表示して停止し、自動再試行や別APIへの切り替えは行いません。共有接続のエラーはその接続の全話者に適用します。
- 音声デバイスの構成変更時は停止します。設定画面から再接続してください。

## アーキテクチャ

- `Contracts`: Unity／Basis非依存の話者・音声・結果と、`ISpeechTranslationEngine`、`IStreamingTranscriber`、`ITextTranslator`。
- `Pipeline`: 音声バッファ、リサンプリング、字幕状態、翻訳要求の集約、および標準エンジン。
- `Grok`: WebSocket、チャンネル割り当て、時刻を保った音声の多重化、Grokイベントの解析。
- `OpenAI`: Chat Completions要求生成、HTTP通信、結果解析。
- `Basis`: 音声購読、話者選択、設定、DPAPI、字幕。

`TranslatorComposition.Create`が具体的な実装を選ぶ唯一の場所です。API単位で変更する場合は対応するインターフェースの実装を交換し、翻訳方式全体を変更する場合は`ISpeechTranslationEngine`を交換します。チャンネル数やWebSocketは共通契約に現れません。Basis本体の変更はアナウンス音声ドライバーの読み取りアクセサーだけです。

## 外部通信なしの検証

`Tests/Editor/LocalProcessingTests.cs`はNUnitのEditModeテストです。Unity Test Runnerで`Net.Minetake.AutoTranslator.Tests`を選んで実行できます。既知の波形・固定JSON・通常のテスト文字列だけを扱い、プロバイダーを接続しません。

対象はPCMのチャンネル分離・無音・上限、リサンプリングのサンプル数と帯域外抑制、チャンネルの再利用禁止・未送信データの引き継ぎ、発話確定と訂正、古い字幕の排除・有効期限、要求の集約、設定検証、DPAPIの往復です。APIサーバーや通信相手のモックは実装していません。

## 後で行う手動確認

実モデル、実通信、VR／デスクトップの会話中の表示品質と遅延は未検証です。次の確認はユーザーが後で実施します。

1. API設定とキーを自分で入力し、デスクトップで1人の途中原文・途中訳文・確定訳文を確認する。
2. 2〜8人の同時発話で、話者と字幕が一致し、他チャンネルの発話や無音が混ざらないことを確認する。
3. 最大話者数を9以上にして、複数接続をまたぐ字幕を確認する。退室・新規参加・上限到達時にも別人の字幕が現れないことを確認する。
4. 通常・ささやき・アナウンスの切り替え、ミュート・ブロック・音量ゼロ・範囲出入り・アバター変更で対象が正しく更新されることを確認する。
5. VRとデスクトップで日本語の可読性、通常チャットとの共存、8秒後の消去を確認する。
6. 無効化、設定変更、音声デバイス変更、通信切断、APIエラーからの手動再接続を確認する。
7. 再起動後の暗号化キーの読み込みと削除を確認し、発話から途中／確定訳文までの遅延を記録する。

この手動確認のためのキー探索・取得やAPI呼び出しを、自動テストに追加しないでください。

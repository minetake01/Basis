# Auto Translator

Windows版Basisの周囲の音声を翻訳するローカル機能です。方式は設定から切り替えます。

- **字幕**: Grok Voice Transcribe 2.0とOpenAI互換のChat Completions API。頭上字幕のみ。
- **音声翻訳**: Qwen `qwen3.8-livetranslate-flash-realtime`。字幕に加え、翻訳音声を話者の位置から再生します。元の声は小さく残します。

初期状態では誰も翻訳されません。モデルのAPIを呼び出すのは、接続設定とAPIキーを保存し、個別プレイヤー画面で翻訳をオンにした相手が発話したときだけです。

## 利用方法

1. WindowsのBasisクライアント／Unity Editorで、設定 → **自動翻訳**を開きます。
2. 方式を選びます。
3. 字幕方式では、xAI APIキー、翻訳APIのベースURL（`https://example.com/v1`のように指定）、モデル名、翻訳APIキー、翻訳先言語を入力します。ローカルホストの翻訳サーバーのみHTTPも使用できます。
4. 音声翻訳方式では、DashScope／QwenCloud APIキー、翻訳先言語を入力します。接続先の初期値は国際リージョン（`wss://dashscope-intl.aliyuncs.com/api-ws/v1/realtime`）です。中国リージョンは`wss://dashscope.aliyuncs.com/api-ws/v1/realtime`に変えます。元の声の音量（初期値20%）で、相手の原音の残り方を決めます。
5. 方式・接続先・APIキー・最大話者数を入力し、**保存して適用 / 再接続**を押します。未保存のキーやURLは使いません。
6. 翻訳したい相手のネームプレートまたはプレイヤー一覧から個別プレイヤー画面を開き、**Audio**タブの**自動翻訳**でオンにします。デフォルトはオフで、プレイヤーごとにUUID単位で保持されます。オフにすると即座にその相手への接続・字幕・翻訳音声を解除します。
7. オンにした相手が話し始めると接続します。頭上に原文と訳文が表示され、途中の原文には `…` が付きます。確定結果は8秒後に消えます。音声翻訳では、訳が話者の口元から通常音量で再生されます。

APIキー欄は保存後に空欄になります。空欄で適用すると保存済みのキーを使います。**停止して保存済みAPIキーを削除**で削除できます。キーはWindowsの現在のユーザーに紐付くDPAPIで暗号化され、`Application.persistentDataPath/net.minetake.auto-translator/`内に保存されます。別のWindowsユーザーへのファイルコピーでは復号できません。

音声・文字起こし・訳文は選んだ方式のAPIへ、利用者自身のキーで送信します。API料金が発生します。音声・会話履歴はローカルに保存せず、字幕と翻訳音声を他プレイヤーに配信しません。共有キーや共有バックエンドは含みません。

字幕はネームプレートの子として描画するため、ネームプレートの表示設定・可視性に従います。通常のチャット表示は変更しません。翻訳対象は個別プレイヤー画面でオンにした相手の通常・ささやき・アナウンスの受信音声で、ミュート・ブロック・個別音量ゼロ・全体音量ゼロは除外します。

## 接続と制限

- 字幕方式のGrok STTはPCM16／16 kHz、100 ms単位のマルチチャンネル送信です。初期設定では8チャンネルを1本のWebSocketで送ります。話者のいないチャンネルは無音です。入力言語は指定せず、自動認識させます。
- 音声翻訳は話者ごとにWebSocket 1本です。入力はPCM16／16 kHz、出力はPCM16／24 kHzです。原文認識はサーバー側で常に有効です。翻訳先は音声出力に対応した言語コードのみです。
- 最大話者数は1〜64。字幕方式は接続ごとに最大8チャンネルです。Grokのマルチチャンネルは2チャンネル以上のため、最大話者数1でも2チャンネル構成（片方は無音）になります。接続数の集約が料金削減になることは保証しません。Qwen側の同時接続・RPM制限はサービス側の値に従います。
- 一度使用したチャンネルを同じ接続内で別の人に割り当てません。必要な接続だけを作り直し、継続中の話者の未送信音声を引き継ぎます。この境界で文字起こしの発話単位は新しくなります。
- 上限時は既存の対象者を維持し、空き枠には発話中の近い相手を入れます。範囲外への移動・退室・ミュート・個別翻訳オフ時は解除し、30秒間発話のない話者も接続枠を解放します。
- 字幕方式の訳文は途中の文字起こしに対して最大1秒に1回、発話確定時にも更新します。話者ごとに実行中1件と最新の待機1件、全体で同時4要求です。APIのストリーミング応答は使わず、要求ごとの完成した訳文を表示します。
- 音声翻訳の原文・訳文は同一接続のストリーミング結果です。翻訳PCMの再生キューは約3秒を上限とし、超えた分は古いサンプルから捨てます。
- 取得バッファ・送信バッファには上限があります。送信バッファは10秒、接続準備は10秒、字幕方式の翻訳要求は20秒を上限とします。認証・通信・形式・バッファのエラーは表示して停止し、自動再試行や別APIへの切り替えは行いません。共有接続のエラーはその接続の全話者に適用します。
- 音声デバイスの構成変更時は停止します。設定画面から再接続してください。

## アーキテクチャ

- `Contracts`: Unity／Basis非依存の話者・音声・結果と、`ISpeechTranslationEngine`、`IStreamingTranscriber`、`ITextTranslator`。
- `Pipeline`: 音声バッファ、リサンプリング、字幕状態、翻訳要求の集約、再生キュー、および字幕エンジン。
- `Grok`: WebSocket、チャンネル割り当て、時刻を保った音声の多重化、Grokイベントの解析。
- `OpenAI`: Chat Completions要求生成、HTTP通信、結果解析。
- `Qwen`: 話者ごとのLiveTranslate WebSocket、3.8のsession/event、PCM16の送受信。
- `Basis`: 音声購読、オプトイン済み話者の選択、設定、DPAPI、字幕、元ボイスのダッキング、翻訳音声の空間再生。

`TranslatorComposition.Create`が具体的な実装を選ぶ唯一の場所です。API単位で変更する場合は対応するインターフェースの実装を交換し、翻訳方式全体を変更する場合は`ISpeechTranslationEngine`を交換します。チャンネル数やWebSocketは共通契約に現れません。プレイヤーごとのオプトインは`BasisPlayerSettingsData.TranslationEnabled`に永続化し、個別プレイヤー画面のAudioタブにトグルを置きます（`com.basis.framework`側の差分はこの2箇所とローカライズのみです）。

## 外部通信なしの検証

`Tests/Editor/LocalProcessingTests.cs`はNUnitのEditModeテストです。Unity Test Runnerで`Net.Minetake.AutoTranslator.Tests`を選んで実行できます。既知の波形・固定JSON・通常のテスト文字列だけを扱い、プロバイダーを接続しません。

対象はPCMのチャンネル分離・無音・上限、リサンプリングのサンプル数と帯域外抑制、チャンネルの再利用禁止・未送信データの引き継ぎ、発話確定と訂正、古い字幕の排除・有効期限、要求の集約、設定検証、DPAPIの往復、Qwen 3.8のsessionとPCM16、発話のdelta連結、再生キューの3秒上限です。APIサーバーや通信相手のモックは実装していません。

## 後で行う手動確認

実モデル、実通信、VR／デスクトップの会話中の表示品質と遅延は未検証です。次の確認はユーザーが後で実施します。

1. 字幕方式でAPI設定とキーを自分で入力し、デスクトップで1人の途中原文・途中訳文・確定訳文を確認する。
2. 音声翻訳方式でDashScopeキーを入力し、翻訳音声が話者位置から聞こえ、元の声が小さく残ることを確認する。
3. 2〜8人の同時発話で、話者と字幕が一致し、他チャンネルの発話や無音が混ざらないことを確認する。
4. 最大話者数を9以上にして、複数接続をまたぐ字幕を確認する。退室・新規参加・上限到達時にも別人の字幕が現れないことを確認する。
5. 通常・ささやき・アナウンスの切り替え、ミュート・ブロック・音量ゼロ・範囲出入り・アバター変更・個別翻訳オフで対象が正しく更新されることを確認する。
6. VRとデスクトップで日本語の可読性、通常チャットとの共存、8秒後の消去を確認する。
7. 方式の切り替え、設定変更、音声デバイス変更、通信切断、APIエラーからの手動再接続を確認する。
8. 再起動後の暗号化キーと個別翻訳オン状態の読み込みと削除を確認し、発話から途中／確定訳文・翻訳音声までの遅延を記録する。

この手動確認のためのキー探索・取得やAPI呼び出しを、自動テストに追加しないでください。
